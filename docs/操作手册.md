## 一、系统简介

数字员工系统是一套**开箱即用的 AI 数字员工管理平台**，让 AI 以"员工"的身份替你干活：

| 它能干什么 | 对应模块 |
| ---- | ---- |
| 招聘数字员工，配置岗位与人设 | 员工管理 |
| 派发任务，快速单发或**多节点编排**（每节点独立选模型） | 任务中心 |
| 处理**图片与文档**（识别图片、提取 PDF/Word/Excel 内容） | 多模态 |
| 产出**真实成果文件**（报告、CSV、笔记），随时下载 | 工作台 |
| 按 cron 定时自动值班（晨报、巡检） | 定时调度 |
| 把任务结果**推送到钉钉/企微/飞书群** | 通知渠道 |
| 与数字员工实时对话（支持发图片） | 在线沟通 |

**大脑**：接入国产大模型（DeepSeek / 通义千问 / Kimi / 智谱 GLM，OpenAI 兼容协议）。未配置模型 Key 时自动进入**模拟模式**——任务照常执行、成果照常产出，只是内容由内置规则引擎生成，可全流程演示。

## 二、安装与启动

### 2.1 本机运行（Node.js 24+）

```bash
# 安装依赖（含前后端）
npm install

# 启动（首次启动自动初始化：4 名数字员工 + 素材样例 + 示例任务 + 定时调度）
npm start

# 打开控制台
#   http://localhost:8787
```

### 2.2 Docker 部署

```bash
docker build -t digital-employees .
docker run -d -p 8787:8787 \
  -v digital-employees-data:/app/server/data \
  -e LLM_API_KEY=sk-xxx \
  -e LLM_MODEL=deepseek-chat \
  --name digital-employees \
  --restart=always \
  digital-employees
```

### 2.3 数据备份（重要）

系统全部资产都在 `server/data/` 目录：

```
server/data/
├── digital-employees.db     # 数据库（员工/任务/对话/调度/日志）
├── inputs/                  # 输入素材区（放真实文件给员工加工）
├── outputs/                 # 成果文件库（员工产出）
└── attachments/             # 上传的图片/文档素材
```

**备份 = 复制整个 `data/` 目录**；恢复 = 停服后把目录放回原位。

## 三、首次配置（3 步上手）

### 第 1 步：配置模型大脑

进入 **系统设置 → 模型大脑**：

1. 点击供应商快捷按钮：**DeepSeek / 通义千问 / Kimi / 智谱 GLM**（自动填入对应端点）
2. 填入你的 **API Key**（在对应平台官网申请）
3. 默认模型保持建议值（如 `deepseek-chat`），保存

> 视觉任务（图像分析）建议选择视觉模型，如 `qwen-vl-max`、`glm-4v-plus`。

### 第 2 步：认识你的团队

系统预置 4 名数字员工，仪表盘可看到全员状态与效能：

| 员工 | 岗位 | 特长技能 |
| ---- | ---- | ---- |
| ✍️ 小文 | 文案策划 | 报告撰写 / 内容总结 / 邮件起草 |
| 📊 小析 | 数据分析师 | 数据整理 / 文件整理 |
| 🌐 小译 | 翻译专员 | 翻译助手 |
| 🛡️ 小安 | 值班巡检员 | 值班巡检 / 文件整理 / 通知推送 |

### 第 3 步：派第一个任务

任务中心 → **＋派发任务** → 标题填"整理工作台素材" → 技能选「文件整理」→ 立即派发。

约 1 秒后任务完成，到 **工作台** 下载它产出的 CSV 清单。

## 四、员工管理

入口：左侧导航 **员工管理**。

### 4.1 招聘员工

点击 **＋招聘新员工**，表单字段：

| 字段 | 说明 | 示例 |
| ---- | ---- | ---- |
| 头像 | 从预设 emoji 中选择 | 🎨 |
| 姓名 | 员工代号，必填 | 小美 |
| 岗位角色 | 决定其专业定位 | 市场分析师 |
| 人设指令 | 系统提示词，定义性格、专长、行为准则（**决定工作质量的关键**） | 见下方示例 |
| 绑定技能 | 勾选其能执行的技能 | 信息收集、报告撰写 |
| 模型偏好 | `auto` 跟随全局 / 指定模型 / `mock` 强制规则引擎 | auto |

**人设指令写法示例**：

```
你是资深市场分析师，负责行业情报收集与趋势研判。
工作风格：数据优先、结论明确、每周输出一份趋势报告。
对外沟通时语气专业、简洁，不闲聊。
```

### 4.2 员工排班

每张员工卡右上角可操作：

- **暂停**：员工暂时休息，不再接收新任务（已排队的任务正常完成）
- **恢复**：重新在岗
- **档案**：查看人设、技能、累计产出、最近任务
- **离职**：删除员工（历史任务与成果保留）

> 注意：**离线员工无法派单**——派发任务时选择已停用员工会被拒绝。

## 五、任务中心

入口：左侧导航 **任务中心**。任务全生命周期：`排队中 → 执行中 → 已完成/失败/已取消`。

### 5.1 快速派单

点击 **＋派发任务**，保持「⚡ 快速任务」模式：

| 字段 | 说明 |
| ---- | ---- |
| 执行员工 | 指定员工，或"自动分派"（系统按任务内容智能匹配员工与技能） |
| 任务标题 | 必填，建议用一句话说明任务 |
| 任务需求描述 | 详细描述目标、输入材料、输出要求（**关键词会触发技能自动匹配**） |
| 技能 | 手动指定，或"自动匹配" |
| 优先级 | 低/普通/高/紧急（紧急任务优先排队） |

### 5.2 任务状态操作

- **取消**：仅对排队中/执行中的任务有效
- **重试**：失败任务一键重建并重新执行
- **详情**：查看任务需求、执行产出、完整日志、节点执行情况

### 5.3 任务描述技巧

任务描述的质量直接决定产出质量。好的描述包含：**背景 + 目标 + 输入材料 + 输出要求**。

```
【背景】Q3 市场活动收官，需要向管理层汇报
【目标】生成一份活动效果总结报告
【输入】活动报名 3200 人，实际到场 2800 人，转化订单 460 单，总营收 128 万
【输出】Markdown 报告，含数据亮点与改进建议
```

## 六、任务节点编排

入口：**＋派发任务 → 切换「🔗 节点编排」**。把一个复杂任务拆成多个节点，按顺序执行，**每个节点可独立选择技能与模型**——这是本系统的核心进阶能力。

### 6.1 节点配置

每个节点有 4 个配置项：

| 配置项 | 说明 |
| ---- | ---- |
| 节点名称 | 如"解析合同"、"提取金额" |
| 技能 | 该节点执行的技能（可为空，自动匹配） |
| 模型 | **本节点专用模型**（如 `qwen-vl-max` 处理视觉、`deepseek-reasoner` 处理推理） |
| 节点指令 | 告诉该节点做什么；支持 `{prev}` 引用上一节点输出 |

### 6.2 上下文传递（{prev}）

节点按顺序执行，上一个节点的输出会自动拼入下一个节点的输入。两种用法：

```
# 方式一：显式引用（推荐，位置可控）
指令：提取合同中的金额与交付周期，{prev}

# 方式二：自然语言触发（自动追加）
指令：基于上一节点的结果做风险分析
```

### 6.3 模型选择建议

| 节点任务 | 建议模型 |
| ---- | ---- |
| 视觉/图像 | `qwen-vl-max`、`glm-4v-plus` |
| 文档解析/文本提取 | `auto`（提取本身不需要模型） |
| 深度推理/数学 | `deepseek-reasoner` |
| 日常文案/整理 | `deepseek-chat`、`qwen-plus` |
| 要求稳定低成本 | `mock`（规则引擎，零费用） |

### 6.4 编排示例

```
标题：合同解析与汇报流水线
 节点1 解析文档    [文档解析]   模型 qwen-plus    指令：解析上传的合同文档
 节点2 整理要点    [数据整理]   模型 auto          指令：把{prev}整理成清单
 节点3 生成简报    [报告撰写]   模型 deepseek-chat 指令：基于{prev}生成管理层简报
 节点4 通知送达    [通知推送]   模型 auto          指令：把简报要点推送给大家
```

执行后，任务详情页可看到每个节点的独立结果与产出文件（`节点N-` 前缀）。

## 七、多模态素材与加工

### 7.1 上传素材

**入口 1**：任务表单底部「素材附件」区，点击 **📎 上传素材**（支持多选）。
**入口 2**：在线沟通聊天框左侧 🖼️ 按钮，直接发送图片。

支持类型与限制：

| 类别 | 格式 | 上限 |
| ---- | ---- | ---- |
| 图片 | PNG / JPG / WebP / GIF / BMP | 单个 ≤15MB |
| 文档 | PDF / DOCX / XLSX / TXT / CSV / MD / JSON | 单个 ≤15MB |

上传后文件存储于 `server/data/attachments/`，可在任务中多次引用。

### 7.2 图像分析（🖼️ 技能）

派发任务 → 技能选「图像分析」→ 上传图片 → 执行后产出**图像分析报告**（内容描述、识别信息、结论建议）。

> 无 API Key 时降级为"图像登记"：输出图片真实元数据（名称/大小/格式），配置视觉模型 Key 后即可真正识别内容。

### 7.3 文档解析（📑 技能）

派发任务 → 技能选「文档解析」→ 上传文档 → 执行后**真实提取**文档文本（PDF 逐页提取、Word/Excel 解包解析），产出解析笔记。

> **文本提取不依赖大模型**，无 Key 也能得到真实的文档内容。

### 7.4 对话发图

在在线沟通中发送图片 + 文字说明，员工（配置了视觉模型时）可看图理解并回复。

## 八、工作台（成果文件）

入口：左侧导航 **工作台**。所有任务产出自动落盘，干完活就有东西交。

### 8.1 成果文件

- **预览**：在线查看（Markdown 渲染、CSV 渲染为表格）
- **下载**：一键下载到本地
- **删除**：清理不需要的成果（不影响任务记录）

文件命名规则：`task-{任务号}-{产出名}.{格式}`，如 `task-17-节点3-工作报告.md`。

### 8.2 输入素材区（重要）

工作台 **「输入素材」** 页签对应 `server/data/inputs/` 目录。**把真实文件放进该目录**（如客户反馈、销售数据、待办清单），然后派发「文件整理 / 数据整理」任务，员工即可读取加工这些真实素材。

```
server/data/inputs/
├── 客户反馈汇总.txt     ← 放进去
└── 销售数据.csv          ← 放进去
        ↓ 派发「文件整理」任务
server/data/outputs/
└── task-6-文件清单.csv   ← 得到成果
```

## 九、在线沟通

入口：左侧导航 **在线沟通**。

1. **新建会话**：选择对话对象（数字员工或系统助手）
2. **发送消息**：Enter 发送，Shift+Enter 换行；🖼️ 可附带图片

> 对话与任务共用同一个模型大脑；无 Key 时对话由规则引擎回复（带"模拟模式"标识）。

## 十、定时调度（自动值班）

入口：左侧导航 **定时调度**。让数字员工 7×24 自动干活。

### 10.1 新建调度

| 字段 | 说明 |
| ---- | ---- |
| 值班员工 | 指定执行人，或自动分派 |
| 调度名称 | 如"每日晨报" |
| 任务内容 | 每次触发时下达的任务指令 |
| 技能 | 每次触发执行的技能 |
| cron 表达式 | 触发节奏（见附录 B） |

### 10.2 快捷模板

点击模板按钮一键填入：

| 模板 | cron |
| ---- | ---- |
| 每 10 分钟 | `*/10 * * * *` |
| 每 30 分钟 | `*/30 * * * *` |
| 每小时 | `0 * * * *` |
| 每天 9:00 | `0 9 * * *` |
| 每天 18:00 | `0 18 * * *` |
| 每周一 9:00 | `0 9 * * 1` |
| 每月 1 日 8:00 | `0 8 1 * *` |

### 10.3 典型值班场景

```
「每日数据晨报」   cron: 0 9 * * *   技能: 文件整理  员工: 小析
  每天 9 点自动盘点素材，生成晨报 CSV

「值班巡检」       cron: */10 * * * *  技能: 值班巡检  员工: 小安
  每 10 分钟生成巡检日志

「晚间行情摘要」   cron: 0 18 * * *   技能: 信息收集  员工: 小美
  每天 18 点抓取指定网页，生成行情笔记
```

每次触发自动创建任务并执行；任务产出自动归档成果 + 同步对话汇报。

## 十一、通知渠道

入口：**系统设置 → 通知渠道**。让数字员工把结果主动推送到你的聊天群。

### 11.1 配置步骤（以钉钉为例）

1. 打开钉钉群 → 群设置 → 智能群助手 → 添加机器人 → 自定义（Webhook）
2. 复制 Webhook 地址（`https://oapi.dingtalk.com/robot/send?access_token=…`）
3. 在系统设置 → 通知渠道：选择渠道类型「钉钉」→ 粘贴地址 → 保存

企业微信 / 飞书操作类似（群内添加"自定义机器人/群机器人"）。

### 11.2 使用

派发任务 → 技能选「通知推送」→ 描述里写清通知内容 → 执行后消息即送达群内。

> 未配置 Webhook 时：推送任务不会失败，而是把通知内容**存档为成果文件**，可在工作台查看。

## 十三、常见场景实操

### 场景 A：每日晨报（零配置，开箱即用）

系统已预置调度「每日数据晨报」（每天 9:00）。验证方式：派发一次「文件整理」任务给小析，产出 CSV 即晨报模板；把真实素材放入 `data/inputs/`，此后每天 9 点自动出报。

### 场景 B：合同解析流水线（节点编排）

1. 任务中心 → 派发任务 → 切「🔗 节点编排」
2. 上传合同文件（PDF/DOCX）
3. 节点 1「解析文档」[文档解析] 指令：解析上传的合同
4. 节点 2「提取要点」[数据整理] 指令：把{prev}整理成合同要点清单
5. 节点 3「通知合同组」[通知推送] 指令：把{prev}推送给合同组
6. 派发 → 约 5 秒后详情页查看三节点结果与成果

### 场景 C：市场情报监控（信息收集 + 定时调度）

1. 新建调度「竞品动态」：cron `0 10 * * *`，技能「信息收集」
2. 任务内容写：抓取 https://xxx.com/news 并整理要点
3. 每天 10 点自动抓取 → 笔记落工作台 → 可再挂一个「通知推送」节点到群里

### 场景 D：客户反馈周报（数据整理 + 报告撰写）

1. 把本周客户反馈汇总成 txt 放入 `data/inputs/`
2. 节点 1「整理反馈」[数据整理]
3. 节点 2「生成周报」[报告撰写] 指令：基于{prev}生成反馈周报
4. 产出：分类 CSV + 管理层周报

### 场景 E：图片票据识别（多模态）

1. 上传票据/截图图片
2. 派发「图像分析」任务（需配置 `qwen-vl-max` 等视觉模型）
3. 产出：识别内容 + 关键信息提取报告

## 十四、故障排查

| 现象 | 原因 | 处理 |
| ---- | ---- | ---- |
| 回复带"（模拟模式）"标识 | 未配置 API Key 或 Key 无效 | 系统设置 → 模型大脑 → 填入有效 Key |
| 模型调用报错 `401/403` | API Key 错误或过期 | 更换 Key；确认供应商平台余额 |
| 模型调用报错 `404` | 模型名不在当前端点 | 确认所选供应商支持该模型（如视觉模型需通义/智谱端点） |
| 任务失败"员工已离线" | 该员工被暂停/离职 | 员工管理 → 恢复在岗，或改派其他员工 |
| 通知任务显示"未配置 Webhook" | 通知渠道未配置 | 系统设置 → 通知渠道填入地址；未配置时内容会存档为成果 |
| 图像分析只有"图像登记" | 无视觉模型 Key | 配置 `qwen-vl-max` 或 `glm-4v-plus` 等视觉模型 |
| 信息收集失败"抓取失败" | 目标站点反爬/不可达 | 更换 URL；目标网站可能屏蔽自动化访问 |
| 上传被拒 | 类型不支持或超 15MB | 查看支持清单（图片/文档类）；压缩文件 |
| 定时调度不触发 | cron 表达式无效 | 新建时校验会提示；对照附录 B 检查格式 |
| 端口被占用 | 8787 已有服务 | `PORT=8888 npm start` 换端口，或停掉占用进程 |
| 控制台打开白屏 | 前端未构建 | 执行 `npm run build -w web` 后重启 |
| 数据丢了 | 误删/迁移 | 恢复 `server/data/` 备份目录（见 2.3） |

## 十五、常见问题 FAQ

**Q1：必须配置模型 Key 才能用吗？**
不需要。未配置时进入模拟模式：工具/多模态技能照常真实干活，文案类由规则引擎生成。配置 Key 后自动升级。

**Q2：支持哪些国产模型？**
DeepSeek（`deepseek-chat` / `deepseek-reasoner`）、通义千问（`qwen-plus` / `qwen-max` / `qwen-vl-max`）、Kimi（`kimi-k2-0711-preview`）、智谱 GLM（`glm-4-plus` / `glm-4v-plus`），以及任意 OpenAI 兼容端点。

**Q3：每节点选不同模型，有什么用？**
按节点任务类型选最优模型：视觉节点用视觉模型、推理节点用推理模型、日常节点用低成本模型——**质量与成本双优化**。

**Q4：任务可以同时跑多个吗？**
可以。执行引擎内置并发池（默认 4 路），多个任务并行执行不阻塞。

**Q5：成果文件在哪？怎么备份？**
`server/data/outputs/`，与数据库同目录。整个 `data/` 目录一起备份即可（见 2.3）。

**Q6：可以接入公司内部系统吗？**
可以。两途径：① 把文件放入 `data/inputs/` 让员工加工；② 「信息收集」技能可抓取内网 HTTP API/页面（需服务端可达）。

**Q7：员工会乱说话吗？**
人设指令（系统提示词）约束其角色与行为；文案类产出可人工复核后使用。

## 附录 B：cron 表达式速查

格式：`分 时 日 月 周`（5 段）

| 表达式 | 含义 |
| ---- | ---- |
| `* * * * *` | 每分钟 |
| `*/10 * * * *` | 每 10 分钟 |
| `0 * * * *` | 每小时整点 |
| `0 9 * * *` | 每天 9:00 |
| `0 9 * * 1` | 每周一 9:00 |
| `0 8 1 * *` | 每月 1 日 8:00 |
| `30 8 * * 1-5` | 工作日 8:30 |
